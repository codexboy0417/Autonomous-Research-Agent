4. TOP 5 TOUGH QUESTIONS & EXACT WINNING ANSWERS
================================================================================

Q1: "How do you ensure the AI doesn't hallucinate citations?"
A1: "We enforce an immutable Article 13 Claim-to-Evidence binding. Agents cannot 
    generate claims freely; every claim must bind directly to an indexed chunk's 
    SHA-256 hash, primary DOI, or official documentation URL. Furthermore, Vera Audit 
    screens every document ID against Retraction Watch databases."

Q2: "Why use Hybrid RRF instead of simple semantic vector search?"
A2: "Dense vector embeddings alone suffer from semantic drift on exact technical 
    terms, version numbers, and DOIs. Lexical BM25Okapi guarantees exact keyword precision. 
    By fusing them via Reciprocal Rank Fusion (RRF, k=60) and pruning candidate overlap 
    above Jaccard θ=0.85, we achieve 92%+ recall with zero redundancy."

Q3: "Where does the official technical documentation come from?"
A3: "Our ingestion engine features a dedicated Platform E layer that maps queries 
    to authoritative, verified documentation manuals—such as Ray Core distributed 
    architecture, PyTorch collective communications, Hugging Face agent contracts, 
    Qiskit manuals, and RFC standards."

Q4: "What is the 5-Factor Reproducibility Rubric?"
A4: "It scores papers across:
    1. Benchmark Dataset Public Availability (20 pts)
    2. Open-Source Codebase & Tests (20 pts)
    3. Method & Hyperparameter Transparency (20 pts)
    4. Containerized Environment Disclosures (20 pts)
    5. Compute Hardware & Profiling (20 pts)
    Total score is out of 100, categorizing research into HIGH, MODERATE, or LOW."

Q5: "Can this system run offline or self-hosted?"
A5: "Yes! The vector indexes run on local FAISS, lexical search runs on in-memory BM25, 
    and the architecture is designed to support quantized local models, eliminating 
    cloud API fees and cutting 3-year TCO by 50% to 65% while keeping all data private."
